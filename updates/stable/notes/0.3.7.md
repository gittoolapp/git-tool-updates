# Git Tool 0.3.7

## What's New

- **New diff layouts and edit highlighting:** The diff toggle is now `Hunk` ·
  `Split` · `Inline`. `Hunk` is the familiar view with collapsed changed blocks
  and per-hunk Stage/Discard. The new `Inline` layout shows the whole file
  top-to-bottom with changes colored in place, and includes the change overview
  ruler in the scrollbar. Whole-file viewing and the `Annotate with Blame`
  control now live under `Inline`, so the view tabs are `Diff` · `Preview` ·
  `Edit` · `History`. The `Edit` view also gains a `Show changes` toggle that
  highlights what you've changed from the base revision as you type.

- **Cleaner commit graph at narrow widths:** As the graph column gets narrower,
  the main trunk stays put while outer branch lanes glide smoothly inward onto a
  shared line, instead of the whole graph shrinking and sliding off-screen. Each
  commit dot keeps its own lane color, and the dots and connectors always stay
  within the graph column.

- **Submodules section hides when empty:** The SUBMODULES section no longer
  appears in the sidebar for repositories without submodules. It reappears — in
  your last expanded/collapsed state — when you open a repository that has them.

- **Vim `zz` / `zt` / `zb` scroll alignment:** In Vim mode, these now scroll the
  focused view so the cursor line (or selected row in lists) sits at the center,
  top, or bottom of the viewport, without moving the cursor or changing your
  selection. Works in the file, diff, and history viewers, the commit graph, and
  the sidebar/staging/commit-detail lists.

## Fixes

- **Branch compare opens with the right base:** Right-clicking a branch and
  choosing **Compare with current branch** now puts the clicked branch in Base
  and your checked-out branch in Head, instead of reversing them.

- **Exact commit dates on hover:** Relative commit dates in the graph and commit
  detail header now show the exact local date and time when you hover over them.

- **Pending conflict zones are visible again:** In the resolution editor, a
  conflict zone still needing a resolution shows its purple placeholder line
  again, so it's clear a resolution is pending.

- **Working-tree files no longer flicker after staging:** Files — especially
  untracked ones — could briefly vanish from the staging panel after staging or
  unstaging, then reappear on the next refresh. They now stay put.

- **Smoother conflict resolution:** Applying or undoing a conflict resolution no
  longer blanks out the panel or jumps around. The card holds its content and
  actions in place with a clear loading indicator while the working tree
  refreshes, then the resolved file moves to staging in one step. Undoing keeps
  the file on screen until it's actually restored.

- **Selected conflict rows keep their own color:** A selected conflict now keeps
  its amber (unresolved) or green (resolved) accent instead of showing a stray
  blue selection bar on top.

- **No flicker when resolving a conflict:** The working-tree list now updates
  like a normal stage/unstage — only the resolved row moves — instead of
  flashing the whole list.

- **Commit graph no longer intermittently shows "No Commits Found":** On a valid
  repository, the graph could occasionally render empty or truncated after a
  refresh. It now loads reliably.
